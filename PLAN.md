# План улучшений AIRun (цикл 2)

> Актуализация: 2026-10. Предыдущий цикл (сборка, smoke-тесты, split router/models, UX дашборда, LLM cache) закрыт. Краткий итог внизу файла.
>
> Приоритет: P0 (ломает или утекает) -> P1 (надёжность петли тренера) -> P2 (продукт на уже готовом API) -> P3 (точечно).
>
> Принцип: чинить наблюдаемое поведение и закрывать его тестом. Не менять auth-заголовки, JWT и схемы БД без отдельной задачи. Garmin и LLM остаются в backend.

---

## P0 — Корректность

### 1. Один `/health` и `/ready`, без утечки текста БД
**Файлы**: `backend/app/main.py`, `backend/tests/test_readiness.py`
**Сделано**: одна пара эндпоинтов. `/ready` проверяет Postgres и Redis, в 503 пишет `unavailable` и не возвращает текст исключения. Тест закрывает утечку текста драйвера и ошибку Redis.

### 2. Ошибки бота без сырого exception
**Файлы**: `bot/handlers.py` (`garmin_password`, `goal_race_date`, `goal_delete`, `stats`, `recommendations`, `sync`)
**Сейчас**: пароль Garmin при ошибке показывает `{exc}` в чат. Создание цели, статистика и рекомендации не ловят ошибку API.
**Сделать**: короткое сообщение на русском. В лог писать тип ошибки, без пароля, MFA-кода и токенов.
**Проверка**: расширить `bot/tests/test_handlers.py`.

## P1 — Надёжность петли тренера

### 3. Уведомления не терять, если бот перезапустился
**Файлы**: `backend/app/workers/tasks.py` (`_notify_telegram`), `bot/main.py` (`notification_listener`)
**Сейчас**: Redis pub/sub. Сообщение живёт только пока есть подписчик. Падение бота в 8:00 теряет утренний дайджест, напоминание о старте и сигнал о новой активности. Два процесса бота получат одно и то же событие дважды.
**Сделать**: очередь (Redis list или stream) с одним потребителем. После успешной отправки в Telegram событие снимается. Ошибку отправки логировать и оставлять событие на повтор.
**Не делать**: не тащить текст рекомендации в очередь. Событие по-прежнему несёт `telegram_id`, тип и id. Текст бот забирает через API.

### 4. Дайджест и напоминание о старте не слать дважды и не терять день
**Файлы**: `backend/app/workers/tasks.py`
**Сейчас**: beat каждый час обходит пользователей и шлёт, если локальный час равен 8 (дайджест) или 7 (старт через 7, 3 или 1 день). Повтор задачи в тот же час шлёт снова. Пропущенный час больше не совпадёт с `days_left`. Утренний дайджест всегда идёт с `force=True` и обходит LLM-кэш.
**Сделать**: маркер "уже отправлено" на пользователя и локальную дату (и на цель для напоминания). Если час пропущен, дослать в ближайший запуск того же локального дня, пока маркер пуст. Повторный дайджест в тот же день не вызывает LLM.
**Проверка**: unit-тесты на час, пропуск часа и повторный запуск. LLM и Telegram мокать.

### 5. Sync по пользователю и расписание, которое не ломается на интервале >= 60
**Файлы**: `backend/app/workers/tasks.py`, `backend/app/config.py`
**Сейчас**: `sync_all_users` идёт одним процессом по всем пользователям. Ошибка одного уже изолирована. Падение процесса обрывает хвост до следующего beat. `crontab(minute="*/N")` при `SYNC_INTERVAL_MINUTES` >= 60 невалиден: поле minute только 0-59. Сейчас в `.env.example` стоит 15, риск латентный.
**Сделать**: beat ставит отдельную задачу на `user_id` с retry на временный сбой Garmin. Интервал перевести на `timedelta` или эквивалент, который принимает значения больше 59 минут.
**Проверка**: тест сборки расписания для 15 и 90 минут. Логи без email и токенов Garmin.

### 6. Тесты connect/MFA и worker-гейтов
**Файлы**: `backend/tests/`
**Сейчас**: есть sync с моком провайдера. Нет тестов на MFA в Redis, на час дайджеста и на дни напоминания.
**Сделать**:
- connect: MFA required кладёт Fernet-blob с TTL, успех удаляет ключ, чужой `telegram_id` не читает чужую сессию;
- worker: чистые функции решения "слать / не слать" без живого Celery.
**Не логировать** пароль и MFA-код в фикстурах сверх того, что уже шифруется в сервисе.

## P2 — Продукт на существующем API

### 7. Дашборд умеет то, что уже умеет API
**Файлы**: `frontend/src/lib/api.ts`, `frontend/src/app/page.tsx`, `goals/page.tsx`, `recommendations/page.tsx`
**Сейчас**: web только читает цели, неделю и список рекомендаций. Создание цели, sync, генерация и статус Garmin есть в API и в боте. Пустое состояние целей отправляет в Telegram.
**Сделать**, без новых контрактов:
- главная: Garmin подключён или нет, `last_error`, дата последней синхронизации (`GET /api/v1/garmin/status`, поле пользователя уже есть в API auth/user);
- кнопка синхронизации (`POST /api/v1/sync/trigger`);
- кнопка "обновить рекомендацию" (`POST /api/v1/recommendations/generate`);
- создание и удаление цели теми же полями, что бот (дистанция, дата, опциональное время).
**Не делать в этом пункте**: ввод пароля Garmin в браузере. Подключение остаётся в боте.
**Проверка**: `npm run lint` и сценарий в браузере: пустой список, ошибка API, повтор, успешные sync и создание цели.

### 8. Часовой пояс пользователя
**Файлы**: `bot/handlers.py`, `bot/api_client.py`, `backend/app/api/v1/routes/auth.py`
**Сейчас**: бот на `/start` всегда шлёт `Europe/Moscow`. От этого часа зависят дайджест, напоминание и "сегодня" в статистике. Повторный `/start` затрёт пояс, если его начнут хранить иначе.
**Сделать**: пункт в настройках бота, валидный IANA-пояс, сохранение через уже существующий upsert. `/start` не перезаписывает пояс, если пользователь его уже задал.
**Проверка**: тест API, что повторный upsert без поля не сбрасывает пояс. Если для этого нужно перестать слать timezone по умолчанию, бот и схема должны остаться совместимыми со старым клиентом.

### 9. FSM бота в Redis
**Файлы**: `bot/main.py`
**Сейчас**: `MemoryStorage`. Рестарт бота обрывает ввод пароля Garmin и мастер цели.
**Сделать**: storage aiogram на том же `REDIS_URL`. Пароль по-прежнему удалять из чата. В логах FSM пароля нет.

### 10. Отдельный лимит на connect и MFA
**Файлы**: `backend/app/api/v1/routes/garmin.py`, `backend/app/limiter.py`
**Сейчас**: общий лимит 120/мин. Пароль Garmin лежит в Redis до 300 секунд (Fernet, ключ `garmin_mfa:{telegram_id}`). На неверный MFA-код можно стучаться всё это окно.
**Сделать**: более жёсткий лимит на `POST /garmin/connect` и `POST /garmin/mfa` (ориентир 5/мин на пользователя, не на IP целиком, чтобы бот за общим адресом не блокировал всех). Ответ 429 с понятным текстом. Ключ MFA не логировать.
**Проверка**: тест rate limit рядом с `tests/test_rate_limit.py`.

## P3 — Точечно, если дойдут руки

### 11. Markdown в сообщениях бота
**Файлы**: `bot/handlers.py`, `bot/main.py`
**Сейчас**: рекомендации и дайджест уходят с `parse_mode="Markdown"`. Символы `*` и `_` из ответа LLM ломают отправку.
**Сделать**: экранировать динамический текст или перейти на HTML с экранированием. Пользовательский текст не менять по смыслу.

### 12. Security follow-up, без смены контракта
Не смешивать с пунктами 1-11.
- `INTERNAL_BOT_SECRET` по-прежнему даёт доступ к данным пользователей. Ротация и отдельная идентичность бота - отдельная задача, заголовки не менять в этом цикле.
- Пароль Postgres `airun` в `docker-compose.yml` только для локальной сети. В production его не использовать.
- Не ослаблять Fernet и не писать MFA payload в логи.

## Не входит в цикл

- Официальный Garmin Developer Program вместо `python-garminconnect`.
- Перенос Garmin или LLM в бота.
- Смена JWT, bot-auth заголовков и публичных схем ответа без отдельной задачи.
- Runtime Zod на все ответы, SEO, пустые `__init__.py`.
- Ввод пароля Garmin в браузере.
